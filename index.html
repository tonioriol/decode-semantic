rsemble: semantic search in ~19 ms and ~129 MB

rsemble searches a large chat corpus, a shelf of project notes, and source code from one Rust process. It keeps the quality of Semble's recipe, BM25 fused with static embeddings, and adds a small neural rerank for chats. It answers faster than Python Semble in 1/37 of its memory.

Each row is a version we shipped or tried. The rerank lifted hit@1 from .533 to .578. Storing its passage vectors at index time cut a search from 230 ms to 42–44 ms, and scanning the vectors on two workers over memory-mapped files to 19 ms. Measured side by side, query by query, the rerank itself adds 2 ms: 19.1 ms with it, 16.5 ms without. Rows are measured on the index of their day; hit@3 moved from .711 to .689 when the fixture was refreshed with newer chats, and the speed changes left every ranking identical.

Physical footprint, decimal MB, on a shared, loaded laptop. Ranges are repeated runs. Python Semble keeps its whole index in RAM; rsemble reads it from disk in place. Documentation stays on by default. The benchmark labels code spans, not documentation. A relevant README can rank above the labelled code, as it does for a URL-routing query in chi. That lowers the code-span score even when the README helps answer the question. The code-only run is a comparison, not the shipped setting.

The benchmark uses repository-averaged, span-aware NDCG@10. Both Rust runs and Python use the v2 embedding model. CPU timings are from the same host on the 19-repository speed subset and exclude model loading and CLI/MCP overhead. Rust cold timings include saving and reopening the index; Python builds in memory. The first-hit metric uses the top 50 chunks and assigns 32,000 tokens to a miss.
